## P0 — Critical (fix before next release)

### P0-1 · Double budget refund corrupts AI token accounting

**File:** `internal/block/aiproxy/handler.go:167–175, 207, 244, 337–347`

`ServeHTTP` registers a `defer` that always calls `h.budget.Refund(…, estimatedTokens, 0, 0)` — with `actual=0` hardcoded. The comment says "actualTokens is set by the response path below" but no such variable is captured by the closure. The actual-usage paths (streaming at line 207, non-streaming at line 244) both call `reconcileAndRefund` _before_ the function returns, which also calls `Refund`. This means for every metered AI request, `Refund` fires twice:

1. `reconcileAndRefund` → `Refund(estimated=N, actual=realTokens)` — correct credit
2. `defer` → `Refund(estimated=N, actual=0)` — credits back all N tokens again

Net effect on `PostgresBudgetStore`: after a request consuming 80 tokens from an 90-token baseline, the counter ends at `90 + 100 − 20 − 100 = 70` — **ten tokens below the pre-request state**. Budget ceilings are bypassed; heavy consumers can over-spend indefinitely.

**Remediation:** Remove the `defer` refund block entirely. `reconcileAndRefund` already handles post-response accounting for both code paths. The deferred pattern was aspirational dead code — the captured variable (actual token count) was never wired up.

### P0-2 · `configUnchanged` ignores backend config changes

**File:** `internal/config/loader.go:134–145`

Backend change detection compares only by name:

```go
oldBackends[b.Name] = struct{}{}
```

If a backend's `config` JSON changes (new upstream URL, updated headers) but the `name` is unchanged, `configUnchanged` returns `true` and the hot-reload is skipped. The gateway continues routing to the stale backend configuration until the process restarts.

**Remediation:** Add a `Checksum` field to `domain.BackendConfig` (parallel to `RouteConfig.Checksum`) and compare checksums in `configUnchanged`. Alternatively, SHA-256 the config JSON inline the same way `ComputeChecksum` does for routes.

### P0-3 · `APIKeyBlock` goroutines lack a lifecycle hook; `Stop()` is never called in production

**File:** `internal/block/auth/apikey/apikey.go:51–55, 336–343`

`NewAPIKeyBlock` starts three goroutines:
- `go cache.Start()` (line 51)
- `go keyCache.Start()` (line 55)
- `eg.Go(drainLastUsed)` (line 74)

`Stop()` exists to drain and halt them, but the `Block` interface (`internal/gateway/block.go`) exposes only `Name()` and `Middleware()`. There is no `Stop()` in the interface and no caller in the production wiring (`cmd/gateway/main.go`, `internal/gateway/block_chain.go`, `internal/gateway/dynamic_handler.go`). On every config reload, `DynamicHandler.Rebuild()` discards the old `BlockChain` and builds a new one. Each rebuild creates a new `APIKeyBlock` and three new goroutines; the old ones are abandoned and run forever.

A concurrent send to the closed `lastUsedCh` channel after an abandoned block's `Stop` is called externally (or never) will panic.

**Remediation:** Add `Stop(ctx context.Context) error` to the `Block` interface. `BlockChain.Shutdown` should call `Stop` on all blocks before releasing them. Wire the shutdown call into `DynamicHandler.Rebuild` (drain old block chain) and into gateway graceful shutdown.

## P1 — High (fix before multi-tenant launch, Day 60)

### P1-1 · Magic PG error code `"23505"` repeated six times without a constant

**Files:** `internal/config/store.go:89,236` · `internal/config/consumer_store.go:45` · `internal/controlplane/store.go:494,714` · `internal/plugin/store.go:105`

The PostgreSQL unique-violation code `"23505"` is a bare string literal at six sites. A typo (already present risk with six copies) would silently pass the unique-violation check, returning a generic 500 instead of a 409 conflict.

**Remediation:** Define `const pgErrUniqueViolation = "23505"` in `internal/config/store.go` or a shared `internal/db` package and reference it across all six callers.

### P1-2 · `OrgContextMiddleware` sends JSON body with `text/plain` Content-Type

**File:** `internal/controlplane/server.go:161–164`

```go
http.Error(w, `{"error":"X-Organization-ID header is required"}`, http.StatusBadRequest)
```

`http.Error` sets `Content-Type: text/plain; charset=utf-8`. The body is JSON. API clients that branch on `Content-Type` will fail to parse the error, breaking contract.

**Remediation:** Replace `http.Error` with `WriteProblem` (already defined in `internal/controlplane/errors.go`) so the response is RFC 7807 compliant.

### P1-3 · `flushAll` writes rate-limit counters under a hardcoded fallback org UUID

**File:** `internal/block/ratelimit/store.go:191–239`

`extractOrgIDFromKey` returns `uuid.MustParse("00000000-0000-0000-0000-000000000001")` on parse failure (line 239). If a key is malformed (e.g., a legacy key without a UUID prefix), all its counter rows are written under org `000…001` — silently crossing multi-tenant boundaries. No error is logged.

**Remediation:** When `extractOrgIDFromKey` fails, drop the batch entry and log a warning (slog.Error) with the offending key. Do not fall back to a synthetic org UUID. Add a metric counter `flexgw_ratelimit_flush_org_parse_errors_total`.

### P1-4 · `PostgresBudgetStore.ReserveWithResult` comment claims `SELECT FOR UPDATE` but issues a plain `UPDATE`

**File:** `internal/ai/budget/reservation.go:50–52`

The struct doc and inline comment say "SELECT FOR UPDATE for pessimistic reservation concurrency control." The actual query is a plain `UPDATE … RETURNING`. While PostgreSQL's row-level lock on `UPDATE` does prevent concurrent modification, the comment creates a false understanding of the locking model and the failure mode differs (an explicit `SELECT FOR UPDATE` with `NOWAIT` would surface lock-wait errors immediately; the current approach blocks indefinitely under contention).

This is a documentation debt with operational consequence: under high concurrency the two-UPDATE sequence within a single transaction can serialize unexpectedly at lock acquisition time without surfacing to callers.

**Remediation:** Either change the first query to a genuine `SELECT … FOR UPDATE` followed by the second UPDATE (explicit semantics), or update the doc comment to accurately describe the current plain-UPDATE lock model. Add a test that verifies hard-enforcement correctness under concurrent reservation.

### P1-6 · `gateway.Server` is dead code

**File:** `internal/gateway/server.go:39–119`

`gateway.Server`, `gateway.NewServer`, `Server.Start`, and `Server.Shutdown` are never referenced outside their own package and `server_test.go`. The production gateway binary (`cmd/gateway/main.go`) uses `gateway.NewDynamicHandler` and `gateway.BuildHandler` directly and never instantiates `gateway.Server`. The struct and its methods are 80 lines of dead code.

**Remediation:** Delete `gateway.Server`. If the abstraction is needed later, it can be re-introduced. Removing it now prevents contributors from accidentally depending on an untested code path.

### P1-7 · `MemoryBudgetStore.Refund` cost calculation is non-functional

**File:** `internal/ai/budget/budget.go:170–219`

`Refund` contains 30 lines of commented-out design notes, discarded approaches, and stacked `if` blocks that shadow the `actualCostUSD` parameter entirely. The only executed cost logic (lines 209–217) divides `entry.currentCostUSD` by a stale token count and credits back a proportional fraction — this is incorrect when multiple consumers share a store or when the entry has been partially refunded. The `actualCostUSD` parameter passed by callers is ignored.

This is an in-memory store used for unit tests and single-instance deployments. Its cost accounting diverges from `PostgresBudgetStore.Refund` (which correctly receives `actualCostUSD` but also ignores it — see P0-1 context). The divergence means unit tests do not catch the production bug.

**Remediation:** Simplify `MemoryBudgetStore.Refund` to match `PostgresBudgetStore.Refund` semantics: `tokenDelta = estimated − actual`; `costRefund = tokenDelta / estimated * estimatedCostUSD`. Store the `estimatedCostUSD` alongside the reservation (requires adding a field to `budgetEntry`) or accept `estimatedCostUSD` as a parameter and compute the refund proportionally. Delete all the dead commented logic.

### P1-8 · `fnv32` allocates a `[]byte` on every rate-limit key hash

**File:** `internal/block/ratelimit/limiter.go:124`

```go
_, _ = h.Write([]byte(key))
```

This converts a `string` to `[]byte`, allocating on the heap on every call. `fnv32` is invoked on the hot path (every rate-limit check and increment, both `LocalLimiterStore` and `DistributedStore`). At 700K+ RPS this is a measurable allocation tax.

**Remediation:** Replace `h.Write([]byte(key))` with `io.WriteString(h, key)`. The `hash.Hash` interface embeds `io.Writer`; `io.WriteString` avoids the allocation when the writer implements `io.StringWriter`. `fnv.New32a()` returns a value that satisfies `io.StringWriter` in Go's standard library.

## P2 — Low (tech debt / cleanup)

### P2-1 · `runtime.ReadMemStats` in deep health endpoint stops the world

**File:** `internal/gateway/health.go:154`

`runtime.ReadMemStats` acquires the GC STW lock. If K8s probes hit `/healthz/deep` at high frequency (common during rolling deploys), this causes periodic STW pauses on the gateway process. The pause scales with heap size and is proportional to GC pressure.

**Remediation:** Use `runtime/metrics` package or `prometheus` gauge snapshots instead. If `ReadMemStats` is kept, document the STW impact and enforce that `/healthz/deep` is not called at probe frequency (use `/healthz` for liveness, `/readyz` for readiness).

### P2-2 · `GatewayConfig.Version` is always `1`; version comparison in `configUnchanged` is dead logic

**File:** `internal/config/store.go:364` · `internal/config/loader.go:118–119`

`LoadGatewayConfig` sets `Version: 1` unconditionally. The `configUnchanged` check at `loader.go:118` compares `old.Version != newCfg.Version` — but since both are always `1`, this branch never fires. The version field adds no signal.

**Remediation:** Either remove the version comparison from `configUnchanged` (rely on route/backend comparisons) or implement a real monotonic version counter (e.g., `MAX(updated_at)` across all active routes and backends).

### P2-4 · `decodeBody` silently truncates oversized request bodies

**File:** `internal/controlplane/handler_routes.go:172–174`

```go
body := io.LimitReader(r.Body, maxBodyBytes+1)
return json.NewDecoder(body).Decode(v)
```

If the client sends a body larger than `maxBodyBytes` (10 MB), the reader is capped at `10MB+1` bytes and `json.Decode` attempts to parse the truncated payload. JSON decoding may succeed on truncated data (if the cut happens after a valid closing brace), silently accepting malformed input. The aiproxy handler uses the correct pattern (`io.ReadAll` then `len(body) > maxBodyBytes` check).

**Remediation:** Apply the same pattern used in `aiproxy/handler.go:parseRequest`: `io.ReadAll(io.LimitReader(r.Body, maxBodyBytes+1))` then `len(body) > maxBodyBytes` check before decoding.

### P2-5 · `convertWildcardPath` comment describes a transformation it does not perform

**File:** `internal/gateway/server.go:254–259`

The comment says "converts /api/v1/* to /api/v1/{path} for chi router compatibility" but the function returns `path` with the same `/*` suffix:

```go
return strings.TrimSuffix(path, "/*") + "/*"
```

This is a no-op transformation with a misleading comment. The `/*` suffix is already the chi wildcard syntax, so no conversion is needed. The confusion may lead future contributors to add an incorrect `{path}` substitution.

**Remediation:** Either delete the function and inline the passthrough, or fix the comment to state that chi already accepts `/*` for wildcard routes.

### P2-7 · `DistributedStore.Start` blocks; callers must spawn it in a goroutine

**File:** `internal/block/ratelimit/store.go:74–90`

`Start()` calls `g.Wait()` and blocks until both internal loops complete. The function name and doc ("launches the sync and cleanup loops") imply non-blocking behavior. The production usage requires `go store.Start(ctx)`, hiding the error return that `g.Wait()` would surface.

**Remediation:** Either rename to `Run(ctx context.Context) error` (explicit blocking contract, mirrors `Watcher.Run`) or change it to spawn the errgroup internally and return immediately, storing the errgroup so `Wait()` can be called at shutdown. The `Run` naming convention matches existing gateway patterns.

### P2-8 · `newTestStore` is an unexported indirection with no purpose

**File:** `internal/ai/budget/budget.go:93–101, 103–106`

`newTestStore` and `NewMemoryBudgetStore` are identical one-liners; `NewMemoryBudgetStore` merely delegates to `newTestStore`. `newTestStore` adds no value and no test isolation that `NewMemoryBudgetStore` does not provide.

**Remediation:** Inline `newTestStore` body into `NewMemoryBudgetStore` and delete `newTestStore`.

### P2-9 · `handleHealthz` in control plane uses `pool.Exec("SELECT 1")` inconsistently

**File:** `internal/controlplane/server.go:130`

The gateway uses `pool.Ping(ctx)` for health checks; the control plane uses `pool.Exec(ctx, "SELECT 1")`. Both are functionally equivalent but produce different latency profiles and error shapes. Consistency aids debugging.

**Remediation:** Replace `pool.Exec(ctx, "SELECT 1")` with `pool.Ping(ctx)` in the control plane health handler.
